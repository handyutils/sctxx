# ARC — Addressable Recall Compaction for Long Context-Window Control in AI Agents

**Authors:** Thang Dang (corresponding), Yuma Ichikawa (corresponding), Sakina Fatima, Koichi Shirahata
**Affiliations:** ¹Fujitsu Research of America, ²Fujitsu Limited Japan, ³RIKEN Center for AIP
**arXiv:** 2607.25066v1 · <https://arxiv.org/html/2607.25066v1> · read 2026-09-11
**Why we read this:** sctxx already has ARC's primitive — an ID-addressable event log, `[evt a–b]` citations, and an explicit recall command (`sctxx expand`) — so the value is not the mechanism but the *systems discipline* around it: what a citation must carry, how a citation catalog stays bounded, what the recall budget is, and two impossibility results that bound what a shipping tool may claim.

## 1. The mechanism, precisely

**1.1 Design principle.** Every baseline "conflates two decisions that need not be coupled: (1) what to keep, and (2) what to show the model right now. ARC separates them. It keeps everything, always, in a content-addressed store; it decides what to show using the same length-bounded logic as the other baselines, but every omission leaves behind an explicit, dereferenceable pointer. Recovery is then a decision that the agent makes, not a probability that the retriever gets right." (L167)

**1.2 Record format.** ID = `Hash(signature(A), O)`, concretely **SHA1 over (action signature ‖ ASCII unit-separator 0x1F ‖ observation)**, with the *visible* id = **first 8 hex characters, extended in 4-character increments only on collision** (L172). Each `ObsStore` record keeps **full content, command signature, fixed head/tail previews, length metadata, return code, creation step, and recall bookkeeping**; the store is **append-only for the lifetime of the task** (L172; Assumption 5, L1211–L1220).
The Appendix models the id *differently*: `id_j = enc_b(j) ‖ fp_d(signature(A_j) ‖ 0x1F ‖ O_j)`, `b = ⌈log2(N_max+1)⌉` (Assumption 4). There "**the occurrence index, rather than the fingerprint, provides uniqueness**", and "none of the proofs assumes collision resistance of SHA1 or of a truncated digest" (L1209). See §3.5.

**1.3 What a citation contains.** "When compaction removes a long observation from the visible transcript, ARC leaves a citation `§id` containing its **fixed head preview, tail preview, metadata, and a `_recall §id` hint**. Observations shorter than ρ remain verbatim. The set `Cited` enforces **citation persistence**: once an id has appeared as a recall handle, later compactions preserve that handle rather than re-summarizing or renaming it." (L174) Cost is pinned: a stub carries id, bounded metadata, bounded previews, a recall hint, with serialized token charge "**at most a fixed constant c ≥ 1**" (Assumption 6, L1224).

**1.4 When compaction fires.** Two modes: **proactive** ("the agent estimates prompt length before each model call and compacts before overflow") and **reactive** ("compaction occurs after a context-window-overflow error") (L183). Evaluation uses the reactive path with a harness-only forced schedule `force_at_calls = (5,10,15)` — "used only in the evaluation, not in deployment, where compaction fires solely on overflow" (L1951–L1953). The routine ("Summarize") is **deterministic and calls no LLM** — "unlike the LLM-summary method, this step adds no extra model invocation or latency". It truncates older thoughts, keeps short observations inline, replaces longer ones with citations, retains recent turns verbatim, and if the result still exceeds `M`, collapses older already-cited stubs to **bare `§id` references** (L180).

**1.5 How the agent recalls.** `_recall §id` is **intercepted by the agent framework before it reaches the environment** (L177). A valid recall injects `ObsStore[id]`; **an invalid id returns a nearest-match suggestion instead of failing silently**. Controlled by a **per-step limit `r` (default r=2)**, a **total materialized-recall budget**, and a **per-recall maximum length**; **LRU recalled bodies are evicted back to citation stubs when the budget is exceeded**. A lighter `_recall_meta §id` restores **only citation-level metadata** (L177). Formally (Assumption 8, L1290–L1314) recall is delivered as **exact, non-overlapping chunks** of ≤ `q` payload tokens via `_recall-start id` / `_recall-next id` with an external cursor: `m_j = ⌈n_j/q⌉`, `a_{j,ℓ} = (ℓ−1)q+1`, `b_{j,ℓ} = min{ℓq, n_j}`, `R_{j,ℓ} = O_j[a:b]`. **"A recall reads only ObsStore; it never invokes `Execute`"** (L1314). Head–tail truncation of a *recalled body* is explicitly forbidden by design: "ARC never recovers a large observation through head–tail truncation, which would irreversibly discard interior tokens" (L191).

**1.6 What the model sees before/after.** Before: `transcript'_i = Serialize(F, S_i, H_i, G_i, U_i)` — fixed prefix, deterministic summary, recent suffix, **one catalog page**, materialized recall buffer — with `tokens(S_i) ≤ M`, `tokens(H_i) ≤ R`, `tokens(G_i) ≤ P`, `tokens(U_i) ≤ Q`, and `K = B + M + R + P + Q + η ≤ L`, where `L = L_ctx − G_max` and `η` is serialization overhead (Assumption 7, L1235–L1288; Def. 3, L1182–L1191). After: the same bounded shape, citations where bodies were, previously recalled bodies LRU-evicted back to stubs. The recent suffix is selected **by token budget `R`, not a fixed number of turn pairs** (L1269).

**1.7 The Fig. 2 algorithm box is not quotable.** In the converted HTML the §"ARC Algorithm (Fig. 2)" section (L169–L185) contains only the prose above; Figure 2 is an image. Appendix B refers to "Algorithm 1" and to "the overflow condition `C_i > L`" (L1941), but Algorithm 1 is absent too. **Do not treat `C_i > L` as a formula from a visible box.** §1.2–1.5 is the complete extractable procedure.

**1.8 Configurations and headline numbers.** `Qwen3-8B @ 16k` and `Qwen3-32B @ 32k`, served with **vLLM**, **4,096-token completion cap**; the window is "prompt plus completion length" (L203–L207, L275–L278, L338). **All of it is Qwen3-specific**: generalization "to other tokenizers, reasoning styles, or instruction-following behavior for the `_recall` convention remains open" (L997).

*NIAH* — needle = 24-char token over a 30-char alphabet in `secrets.txt`; 1000 tasks × 3 seeds (42/82/122) = 3000 attempts/method (Table 2, L475, L509–L516). Mean accuracy, 8B / 32B / mean of the two:

## 2. The ablation on `recall_budget`

Five parameters, each trading "how often the compaction fires against how much of ObsStore is allowed back into the visible transcript at once" (L1937): `max_model_len` (L) default **16,384** — at `L→∞` "ARC, Auto-Compact, and full-context converge because none of them are ever invoked" (L1941); `recall_budget_chars` default **16,000** — total character budget for observations *currently materialized*; **ObsStore itself is never bounded**, and on overflow "the least-recently-used materialized observation is evicted back to its citation stub" (L1945); `recall_max_chars` default **8,000** — max size of one `_recall` response, and a larger stored observation "is windowed to a head/tail excerpt rather than injected in full — the same head+tail structure used in the citation stub, just with a larger window" (L1949); `force_at_calls` default (5,10,15), evaluation-only (L1953); `noise_lines_per_side` default 25 (≈4.5k chars), a harness parameter sitting above the **500-character keep-verbatim threshold used by all lossy baselines** (L1957).

**Sweep.** Jointly `RECALL_BUDGET_CHARS`/`RECALL_MAX_CHARS`. LongBench: 3 levels — 8k/4k, 16k/8k, 32k/16k — both scales. NIAH: 4 levels — additionally 4k/2k — on **Qwen3-8B only** ("For saving the computational cost"), n = 1000 (L2018–L2022). Accuracy = Success/(Success+Fail).

**NIAH — monotone and saturating.** ARC 92.5% → 93.2% → 99.1% → 99.4% across 4k/2k → 8k/4k → 16k/8k → 32k/16k, "with the large jump occurring at 16k/8k and only **+0.3pp** gained from doubling the budget again" (Table 7, L2024–L2025). Margin over the next-best method: +12.5pp at 4k/2k, +14.8pp at 8k/4k, +20.3pp and +20.1pp after. Baselines are budget-insensitive — Full_context 35–40%, Sliding_window 53–57%, RAG_memory 77.5–80.0% across the whole sweep (L2027–L2031).

**LongBench — inverted U, peak at the intermediate level.** ARC 8B: 26.05% → **29.26%** → 27.33%; ARC 32B: 29.90% → **34.08%** → 33.76% (L1973–L1974; Table 8). "In both cases the peak occurs at the intermediate 16k/8k budget rather than the largest. This indicates ARC's recall mechanism benefits from a moderate, well-targeted budget and **degrades once the budget grows large enough to admit lower-relevance content**" (L1974). At the smallest budget ARC is *not* best: Sliding_window leads at 32B (31.19% vs 29.90%) and LLM_summary/Structured_state edge ARC at 8B (26.69/27.01 vs 26.05) — "ARC requires a minimum recall budget to construct a useful memory structure, which we note as a limitation under very tight budgets rather than omit" (L2008). Baselines show no such peak: Structured_state falls 27.01% → 21.22% (−5.8pp) on 8B as budget grows (L2011).

**What the paper recommends:** *nothing explicitly.* It reports 16k/8k as the LongBench optimum and the NIAH knee, and these **are also the defaults** (16,000/8,000). Reading the defaults as the recommendation is inference, not quotation.

**Two caveats on the ablation tables.** (i) Table 8's LongBench runs report Success/Fail over n=311 (one pass) while Table 1's headline figures are 933-attempt means; the paper does not say which seed Table 8 used, so the 29.26% (Table 8) vs 27.47% (Table 1) gap at the same nominal 16k/8k is unexplained rather than provably contradictory. (ii) Likewise Table 7's 16k/8k NIAH value (99.1%, 991/1000) vs Table 2's 8B 99.00% (2970/3000) is a single-pass vs 3-seed comparison.

## 3. The formal results, stated honestly

**3.1 The model (Appendix A, L1173–L1314).** `O_i = (O_1…O_{N_i})` are **tool observations** from normal environment actions, `n_j = |O_j|` (Def. 2); `L = L_ctx − G_max` (Def. 3). Assumptions: (4) injective fixed-width occurrence ids; (5) append-only store written **before any compaction can remove** `O_j`; (6) persistent external catalog, constant-cost stubs, page capacity `p`, **only one page materialized**, `pc ≤ P`; (7) the five-component budget `K = B + M + R + P + Q + η ≤ L` enforced **before every model invocation**; (8) recall as exact `q`-token non-overlapping chunks that never call `Execute`.

**3.2 What is proved.** **Prop. 9 (impossibility of all-visible citation persistence), L1316–L1350:** if all `n` citation stubs must remain simultaneously visible and each costs ≥ `c_min > 0`, **no constant `K` bounds the active prompt for arbitrary `n`** — take `n* = ⌊K/c_min⌋+1`, then `C(n*) ≥ n*·c_min > K`. Hence "persistent citation addressability must instead be maintained in external state, with only a bounded page or subset materialized in the active prompt at any given time" (L1349). **Lemma 10** identifier uniqueness (from injectivity of `enc_b`); **Lemma 11** uniform active-view bound independent of `i` and `N_i`; **Lemma 12** every stub sits on exactly one page, page cost ≤ `P`, reachable within `⌈j/p⌉ ≤ ⌈N_i/p⌉` page materializations; **Lemma 13** the chunks are a disjoint, ordered, exhaustive partition of `O_j`; **Cor. 14** `n_j/q ≤ m_j < n_j/q + 1` and total serialized recall `≤ n_j + ρ(n_j/q + 1)`.
**Theorem 15 (L1631–L1867)**, for any execution satisfying Assumptions 4–8 with `N_i ≤ N_max`: (1) prompt safety `tokens(transcript'_i) ≤ K ≤ L`; (2) stable archival fidelity `ObsStore_t[id_j].full_content = O_j` at all later `t`; (3) persistent finite discoverability, ≤ 1 page of cost `P` visible; (4) exact address-conditioned recall in `m_j = ⌈n_j/q⌉` responses without `Execute(A_j)`; (5) **observational** losslessness — the ordered observation history is reconstructible and the map is injective; (6) active-view bound independent of `i, N_i` while archived payload is `Σ n_j` tokens, excluding metadata.
**Prop. 17 (L1873–L1890):** for any deterministic memory system receiving an arbitrary `N`-bit history, with ≤ `2^κ` distinguishable active states and ≤ `2^s` external states, exact recovery requires `s ≥ N − κ`, hence `s ∈ Ω(N)` for fixed `κ`. "A prompt backed by κ fixed binary storage cells is a special case because it has exactly `2^κ` possible cell configurations." **Cor. 18** append-only ARC stores exactly `N` payload bits, over the `N − κ` bound by the additive `κ` bits, and `N/(N−κ) → 1`, so it is "asymptotically optimal to first order". **Remark 19:** worst-case only; compressible histories may need less; metadata excluded; the point is that "a bounded active prompt and exact recoverability cannot both be achieved with **constant total memory**".

**3.3 What is *not* proved — the scope remark is load-bearing.** Remark 16 (L1869–L1871): Theorem 15 "does not prove that the language model will select the correct identifier, issue enough recall commands, or solve the downstream task correctly. It is also an **observation-losslessness** theorem. If the paper wishes to claim full-transcript losslessness, then every discarded action and every discarded reasoning record must also be archived under the same append-only discipline."

**3.4 Practical consequence for a tool that must ship.** (a) **Prop. 9 forbids** any artifact whose citation list grows with the session — "list every omitted item" is *provably* not boundable however small each line is; a bounded citation page plus a deterministic finite scan to the rest is the only length-independent shape. (b) **The lower bound forbids** "lossless handoff inside a fixed artifact size": bytes that leave the artifact must exist elsewhere and grow linearly in the worst case, so a tool may claim *exact address-conditioned retrievability*, never *lossless compaction at constant total size*. (c) **Theorem 15 is a mechanism theorem, not a task-success theorem** — "the id resolves and the bytes are exact" is a property a deterministic verifier can check offline; whether a reader asks for the right id is out of scope. (d) Of the empirical numbers, only the NIAH gap is load-bearing for the *mechanism* rather than the model, because that task isolates verbatim recall, exactly what the theorem covers.

**3.5 A gap in the paper.** The *described* id (L172: SHA1 content hash, 8-hex visible prefix, 4-char collision extension) is **not** the id Assumption 4 proves unique (index ⊕ fingerprint, uniqueness from the index, collision resistance explicitly not assumed). Uniqueness under the deployed content-hash scheme is not established. Same collision with `ρ`: L174 uses `ρ` as the length below which an observation stays verbatim, while Assumption 8 (L1292) defines `ρ ≥ 0` as recall response-wrapper cost; Appendix B's real keep-verbatim threshold is **500 characters** and applies to the *lossy baselines* (L1957). No sctxx design should treat "SHA1 id + collision extension" as proven.

## 4. What sctxx could adopt, deterministically (no LLM in the loop)

Ranked by guarantee gained per unit of change. Stages are spec §7–§12 (S0 parse → S1 ledgers → S2 mask/segment → S3 fold → S4 tail → S5 verify/reconcile → render L0–L3).

| # | Change | Where it lives | LLM-free? | Paper anchor |
|---|---|---|---|---|
| A1 | Bounded catalog page replaces unbounded omitted-item footer | render L1 + L3 (`render.rs:855`, `:837`) | yes | Prop. 9 / Lemma 12 |
| A2 | Exact non-overlapping chunked `expand` output | `src/cli/discover.rs` `expand` | yes | Assumption 8 / Lemma 13 |
| A3 | Enforced `K ≤ L` against the receiving model, named budgets | S2 budgets + render + `extract` flags | yes | Thm 15 claim 1 / Assumption 7 |
| A4 | Self-sufficient, cost-capped citation stubs | render L1 item lines | yes | Assumption 6 / L174 |
| A5 | Published handles are never renamed | S5/S3 item-id derivation | yes | L174 (`Cited`) |
| A6 | Resolution + coverage checks in `verify` | S5 | yes | Thm 15 preconditions |
| A7 | Recall convention documented | `skill/SKILL.md` | n/a | L177, L1949 |
| A8 | Report the six-term budget split | `report.json` | yes | L1269, Eq. 15 |

**A1 — Replace L1's unbounded omitted-item list with a bounded catalog page. (highest value).** `src/pipeline/render.rs:855` emits `omitted.join(", ")` for **every** budget-omitted item id, and `render.rs:837–851` emits every reversed decision/constraint/goal — both are all-visible citation lists. **Change:** cap each at `p` stubs, emit `page s/⌈N/p⌉`, and expose page `s` through a documented deterministic command (`sctxx show state.json --items-page <s>`, i.e. Lemma 12's `catalog-next`), naming that command and the page count in **L3** beside the existing expand template. **Why:** this is where sctxx currently violates Prop. 9 in shipped code — `--budget` does not actually bound the artifact, because the footer is O(number of items). **Cost/risk:** new CLI surface ⇒ CLI-contract + `xtask gen-skill` + schema/version notes (AGENTS.md rule 7); needs a stable total order (sorted vectors, never HashMap order); `p` and `c` become documented tunables.

**A2 — Exact chunked `expand` instead of unbounded or head/tail output. (high value, cheap).** `expand <session> a..b` today dumps the whole raw range into the receiver's window with no cap. **Change:** add `--max-payload q` and page the output into **non-overlapping** chunks, printing `m = ⌈n/q⌉` and a `_recall-next`-style follow-up command; never window the middle away. **Why:** Assumption 8 + Lemma 13 give exactness, and L191 rejects head–tail windowing *for recovery* because it "would irreversibly discard interior tokens" — copy the recall half of ARC, not the preview half. **Cost/risk:** low; pure Rust plus a flag; must use the vendored UTF-8-safe truncation and the shared 4-bytes/token estimator; keep `--context N` compatible.

**A3 — Enforce `K ≤ L` at write time with named component budgets. (directly from Thm 15, cheap).** **Change:** add `--model-context L_ctx` and `--max-completion G_max` to `extract`; compute `L = L_ctx − G_max` and `K = B + M + R + P + Q + η` from the artifact's real pieces (brief + items + tail + catalog page + recall reserve + *measured* overhead `η`), and **fail through the §3.1 exit-code path when `K > L`** rather than emit an overflowing artifact; print all six terms in `report.json`. **Why:** Theorem 15 claim 1 is the one part that transfers to a static artifact verbatim ("before every model invocation" ⇒ "before the artifact is written, against the receiving model"). Today `--budget 8000` is best-effort and the tail is counted separately (spec §12.2), so no single number is ever checked against the reader's window. **Cost/risk:** two new flags and a hard failure mode are user-visible contract changes (`--budget` semantics); if `η` is assumed rather than measured, the check is theater.

**A4 — Citation-record contents: make a stub self-sufficient and cost-capped.** **Change:** today a citation is a bare span (`[evt 4122–4381]`). Adopt ARC's stub shape — span + **bounded head preview** + **bounded tail preview** + metadata (kind, event count, first/last timestamp, success/error where applicable, redaction status) + the exact `sctxx expand` command — with each stub capped at `c` tokens (Assumption 6). **Why:** ARC's case for why omission is safe rests on the stub being dereferenceable *and* informative enough to decide whether to dereference; a bare span forces a recall merely to triage. **Cost/risk:** every retained stub costs more, so `p` must shrink or the item budget retune; previews must be redacted (§10.2) and truncated with the vendored helper, and hard-capped or they re-introduce unbounded growth.

**A5 — Pinning rule: a published handle is never renamed. (medium value, low cost).** ARC's `Cited` set preserves a handle once it has appeared (L174). For sctxx: item ids and evt spans already emitted in a previous artifact must keep their identity across re-extraction when the underlying events are unchanged — derive ids from (span, kind, content hash) under a declared capacity, **not from emission order**, which is Assumption 4's actual lesson (uniqueness from the index, not the digest). **Why:** a receiving agent may cache L0/L1 across a re-run; renaming invalidates the recall path already written into its own transcript. **Cost/risk:** changes id derivation ⇒ `insta` snapshot churn and a `handoff` schema note; must be deterministic and collision-checked against `N_max`.

**A6 — Deterministic S5 verify checks.** Add to `sctxx verify`: (a) every `[evt a–b]` resolves — `a ≤ b`, `b < event_count`, and all referenced events survive the active-branch filter; (b) measured `K ≤ L` (A3); (c) citation ids pairwise distinct, and each id's page computable from the artifact alone (Lemma 12); (d) each source file's **hash and length** recorded and re-checked when still readable — L3 today records one `source_hash` for the primary source only (`render.rs:1243`), thinner than Assumption 5's "written before any compaction can remove it"; (e) each stub's cost ≤ `c`. **Why:** these are exactly the preconditions Theorem 15 is conditioned on, all checkable without a model. **Cost/risk:** low, but keep them **separate** from §10.3's LLM probes — a passing probe does not establish resolution, and a passing resolution check says nothing about whether an agent recalls correctly (Remark 16).

**A7 — Publish the recall convention in `skill/SKILL.md`. (low cost, honest scope).** Document the per-step recall limit `r` (ARC default r=2, L177), the per-recall cap (ARC default 8,000 chars, L1949), and metadata-first lookup (`sctxx show state.json --item D14` as the `_recall_meta` analog, already hinted in §12.2). **Why:** sctxx cannot enforce these (§5), so a documented convention is its only lever over reader behavior, and the paper's defaults are a defensible starting value. **Cost/risk:** documentation only; label it a convention, never a guarantee.

**A8 — Report the budget split, not one budget.** Print `B, M, R, P, Q, η` in `report.json` so A3 is auditable. Note `R` is already budget-selected rather than turn-count-selected (`--tail`), matching Assumption 7's requirement (L1269) — a point in sctxx's favor.

## 5. What does NOT transfer

1. **The interception point does not exist.** ARC's `_recall §id` is caught by the agent framework *before the environment* (L177), and `r`, the total materialized budget, and LRU eviction are *framework-enforced*. sctxx emits a file an agent it does not control reads later, so nothing in ARC's runtime discipline is enforceable — A7 is documentation, not a bound, and A1/A2 bound only sctxx's own output, not the reader's cumulative context.
2. **The store is not sctxx's to keep.** Assumption 5 requires the record to be written **before any compaction can remove it** and never overwritten/truncated/deleted "during the task" (L1211–L1220). sctxx's archive is the provider's session file: rotatable, prunable, redactable, or appended to by a resumed session. Theorem 15 claim 2 is therefore *not* inherited; the honest claim is "the pointer resolves if the hash still matches" — which is why A6(d) matters. A resumed session also shifts every later event index, silently changing what an old citation means; ARC's append-only store structurally cannot have that failure mode.
3. **Observation-losslessness ≠ transcript-losslessness.** Def. 2 covers tool observations from environment actions, and Remark 16 excludes discarded reasoning traces "unless those traces are also stored verbatim" (L1180, L1871). sctxx cites reasoning, user messages, plans, assistant finals, and git state — a much wider surface. The IR keeps all of them, but that is sctxx's own property: **no part of Theorem 15 covers it**, and any sctxx losslessness claim must be per-event-kind and backed by sctxx's own check.
4. **There is no fold to be deterministic.** ARC's compaction is LLM-free by construction (L180), which is why it adds no model invocation or latency. sctxx's S3 fold *is* an LLM stage (§8) with deterministic apply/validation (§8.3–8.4). The transferable rule is weaker but real: **every event the fold summarizes away must still be reachable by evt range** — the fold may never be the *only* record of anything. That is checkable in S5 (A6a) and costs nothing.
5. **The cost numbers are about serving, not writing files.** 38.8% / 73.5% / 80.3% and Tables 3–4 are roofline estimates over replayed trajectories parameterized by KV-cache footprint, decode batch size `N_b`, and HBM capacity (Eqs. 1–2). sctxx serves no inference and cannot re-derive or contradict them; they motivate a smaller reader context, not a measurable property of sctxx.
6. **Prop. 9/17 constrain a *prompt*, and sctxx's artifact is prompt-shaped only when fully loaded.** If the reader loads L0 only (`--layers L0`), the bound applies to that projection and the rest plays the external-catalog role. The consequence is that sctxx must *declare which projection is guaranteed to fit `L`* — A3 plus an explicit layer-budget statement (§12.2), not a new mechanism.
7. **Model-specific results.** Everything empirical is Qwen3-8B/32B with vLLM and a 4,096-token completion cap, and generalization beyond the Qwen3 family is open (L997). No sctxx decision should hinge on the LongBench margin (+1.64/+1.80 points), which the paper itself says is "better interpreted as a lower bound" on the failure attributable to recall (L989).

---

## 6. Verdict: **adopt-partially**

ARC's mechanism is already sctxx's shape — append-only index-addressable log, `[evt a–b]` pointers, explicit `expand` recall — so the paper hands sctxx no new architecture, and its accuracy gains (99.40% vs 88.12% NIAH; 29.97% vs 28.25% LongBench-v2 Hard; two Qwen3 scales only) are evidence the *idea* is sound rather than transferable measurements. Worth adopting is the load-bearing, model-free half of the systems discipline: (i) Proposition 9's ban on all-visible citation lists, which sctxx currently violates in shipped code through the unbounded footer in `render_items`; (ii) Assumption 8 / Lemma 13's exact non-overlapping chunk discipline for recall, replacing unbounded or head/tail `expand` output; (iii) Theorem 15 claim 1's enforced `K ≤ L` check with named component budgets, computed against the *receiving* model's window at write time; (iv) the citation-stub contents and the `Cited` pinning rule; (v) a deterministic S5 check set for exactly the preconditions the theorem assumes. What must be rejected is anything stronger: Theorem 15 is an **observation**-losslessness, mechanism-level result whose append-only premise sctxx satisfies only by courtesy of a provider-owned session file it does not control, and Proposition 17 shows "lossless handoff at constant total size" is not merely hard but impossible. Adopt the bounds and the record format; refuse the word "lossless".
