# T2419 — verifying the seeding rows against real launches

**Date**: 2026-09-11 · **Host**: Apple M1 Max, `aarch64-apple-darwin`
**Versions**: Claude Code `2.1.268`, Codex CLI `0.153.4`, Pi `0.85.1`
**Artifact**: a real deterministic handoff (`sctxx extract <real session> --llm none`) into a scratch
directory — 58 KB `handoff.md`, five files, no model involved in producing it.

## What was being tested

[ADR 0004](../../../docs/adr/0004-handoff-launch-and-seeding.md) recorded its rows as **probed, not
verified**: the flags existed and the semantics were documented, but no artifact had actually reached a
model through them. The question here is narrower and answerable: **does the artifact's content arrive
in the receiving agent's first turn?**

The test is a content-level one, not a flag-parsing one. The artifact contains the source session's id,
and **the pointer sentence sctxx generates does not**. So an agent that answers with that id has read
the *handoff*, not just the prompt.

## Results

| # | Agent | Route | Exact command (abridged) | Result |
|---|---|---|---|---|
| 1 | Claude Code 2.1.268 | file | `claude --append-system-prompt-file <handoff.md> -p "<question>" --no-session-persistence` | **verified** — exit 0, 12.0 s, returned the session id from the artifact |
| 2 | Pi 0.85.1 | file | `pi --append-system-prompt <handoff.md> -p "<question>"` | **verified** — exit 0, 15.0 s, returned the session id |
| 3 | Codex CLI 0.153.4 | pointer | `codex exec --skip-git-repo-check --sandbox read-only --ephemeral "<pointer> <question>"` | **verified** — exit 0, 20.5 s, 26k tokens, read the file itself and returned the session id |
| 4 | Claude Code 2.1.268 | file, **interactive** | `claude --append-system-prompt-file <handoff.md> "<pointer>"` | starts the real TUI in a PTY — then stops at the trust prompt (see below) |
| 5 | Codex CLI 0.153.4 | pointer, **interactive** | `codex "<pointer>"` | starts the real TUI in a PTY — then stops at the trust prompt |

`-p` / `exec` were used for rows 1–3 so the run terminates and the answer is machine-checkable. That is
the same seeding flag with the same value; only the "and now stop" part was added. Row 3 additionally
appended the question to the pointer, because Codex's channel is the pointer itself — the property under
test, "the agent can reach the artifact from the pointer", is unchanged by that.

## The finding: both agents gate an unfamiliar directory behind their own trust prompt

Neither interactive launch reached a first turn, and neither failed. Both stopped at a prompt of their
own:

```text
Accessing workspace: /private/tmp/t2419
Quick safety check: Is this a project you created or one you trust?
❯ No, exit
  Yes, I trust this folder
```

```text
> You are in /private/tmp/t2419
Do you trust the contents of this directory? Working with untrusted contents comes with higher risk of
prompt injection.
```

This is the correct behaviour and **sctxx must not bypass it** — `--dangerously-bypass-…` exists on both
CLIs and is exactly the flag a handoff feature should never reach for. It is also not a defect in
practice: a real handoff starts in the session's own project directory, which the developer has already
run that agent in.

It was a surprise the *feature* was creating, though: the pane says "this exact command will run" and
nothing about the first thing the developer will actually see. So the confirming pane now says:

> a directory the agent has not seen before will ask to be trusted first.
> that prompt belongs to the agent: sctxx never bypasses it.

## What is still not verified, and why

- **First-turn delivery in the interactive form.** Reaching it requires either accepting trust on a
  scratch directory (a persistent change to the developer's agent config, on their behalf, for a test)
  or launching into a real project, where the handoff says "continue the work" and the agent would
  begin doing it. Neither is a test's decision to make. Rows 1–3 establish that the *channel* delivers
  the artifact, and rows 4–5 establish that the interactive form starts; what is unproven is only the
  join between them, past a prompt that belongs to the agent.
- **Resumability.** The launched session is the agent's own session, so `claude --resume` / `codex
  resume` can reach it — but that was not demonstrated here. The interactive runs exited at the trust
  prompt before a session was written, and relocating the agent's home to keep the test out of the real
  store (`CLAUDE_CONFIG_DIR`) also relocates its credentials: the run answered `Not logged in · Please
  run /login`. A session record *was* still created, which shows the store is written independent of
  the model call, but that is not the same as a resumable successful session.

## What this changes

- ADR 0004's Claude and Pi file rows and the Codex pointer row move from **probed** to **verified** for
  content delivery, on the versions in the table.
- The confirming pane gained the trust-prompt heads-up, because a measured surprise should not be left
  to be discovered.
- ADR 0004's headless form (`codex exec -`, artifact on stdin) was exercised as row 3's mechanism and
  works; it remains unimplemented in the TUI because nothing consumes it yet.
